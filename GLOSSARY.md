Este glossário existe para que backend, frontend e qualquer outro
repositório do projeto usem os **mesmos termos com o mesmo significado** —
tanto em conversas entre humanos quanto em nomes de campos, endpoints,
eventos e variáveis no código.

Regra geral: se um termo de negócio aparece em mais de um repositório (um
campo de API, um conceito de domínio, um status), ele deve estar aqui, com
uma única definição.

## Como usar

- **Ao adicionar um termo novo:** inclua o termo em português (se for como
  o time fala) e, se aplicável, o termo equivalente em inglês usado no
  código (variáveis, campos de API).
- **Em caso de divergência:** se dois repositórios usam nomes diferentes
  para o mesmo conceito, isso é um sinal de que o termo precisa ser
  resolvido aqui e depois alinhado nos repositórios — abra uma issue com o
  template "Decisão de arquitetura a discutir".
